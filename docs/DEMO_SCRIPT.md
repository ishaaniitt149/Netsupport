# 10-Minute Technical Manager Demo Script

**Pre-requisite:** Ensure the local backend is running (`make run`) and the Streamlit UI is launched (`make demo`). 

## Phase 1: The Predictive Operations Dashboard (0:00 - 0:02)
* **Action:** Navigate to the "Device Risk" tab in the Streamlit UI.
* **Talking Track:** 
  "Welcome to the operations dashboard. Instead of waiting for a network node to fail, our predictive Machine Learning model scans telemetry across the fleet. Notice `RTR-DEMO-001` — it's currently showing an elevated risk score. The model highlights increasing CRC errors and packet loss. We haven't experienced an outage yet, but we have a preventive window."

## Phase 2: Simulating the Incident (0:02 - 0:04)
* **Action:** Navigate to the "Demo Mode" tab and click **RUN DEMO SCENARIO**.
* **Talking Track:** 
  "Let's simulate what happens if we ignore that warning. The simulation progresses through stages: packet loss increases, interface flaps occur, and finally, a `NODE_DOWN` alert is generated by the monitoring system. Watch as the platform automatically correlates these independent alerts into a single unified incident."

## Phase 3: Deterministic RCA Generation (0:04 - 0:06)
* **Action:** Click into the generated Incident Detail view.
* **Talking Track:** 
  "Instead of an engineer logging in via CLI to run `show tech-support`, our system automatically retrieves and parses the diagnostics using a deterministic rules engine. 
  Notice the RCA explicitly cites the exact evidence: 'CRC Errors: 1450', 'Packet Loss: 17%'. There are no LLM hallucinations here—this is pure programmatic parsing, ensuring the technical truth is preserved."

## Phase 4: Resolution & KB Authoring (0:06 - 0:08)
* **Action:** Show the "Resolution" submission and navigate to the "Knowledge Base" tab.
* **Talking Track:** 
  "Once the engineer replaces the faulty fiber, they log the resolution. Now, the system's LLM takes over to do what it does best: summarize. It drafts a version-controlled Standard Operating Procedure (SOP). Notice how the SOP is firmly grounded in the exact metrics from our deterministic engine. This is now available for future incidents."

## Phase 5: Business Value Review (0:08 - 0:10)
* **Action:** Show the KPI/Analytics overview (or discuss the Databricks architecture).
* **Talking Track:** 
  "Because this SOP is now registered, the next time this exact failure signature occurs, an L1 or L2 engineer will be handed this exact, verified playbook. This reduces our reliance on senior engineers, drives down Mean Time To Resolve, and allows us to track exact ROI based on our measurement framework."
